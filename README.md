> 遵守 `ops/底座生成前必读_效率与技术栈.md`。FastAPI + Vue 3 + SQLite，交付须 docker compose 一键起；库用 SQLite，不挂外置 Postgres。  
> **禁止同构换皮**：本仓主链路、表结构、接口与页面均独立，不得与其它仓共用同一套 `/api/items` 壳。

## 骨架一句话

业务日分区切片登记后裁决完整度，完整才放行下游，并与消费水位对账

迟到切片、重切、跨分区依赖、部分完整冻结、消费水位回拨

## 避开

别做成作业拓扑编排换皮；别做成纯水位大盘

## 互斥切口候选

- 迟到切片整批拒收 vs 进待补齐冻结区
- 重切失败整笔回滚 vs 保留已完整分区
- 放行与水位同步闸 vs 异步放行后纠偏

## 当日放行策略锁定（中途改口缺陷修复）

当日策略按业务日钉死（`release_policy` 表），甲乙正确性口径与互斥账本择一执行，策略锁定说明随钉死原样落库，页面四处（策略页、审计列表、目录旁注、放行流水详情条）同源对读。

- **甲锁定（默认，同步闸）**：当日已有任一放行尝试（成功/拒绝/冻结，以未作废流水计）后，改口一律拒绝并返回「策略已锁定」，同时写「策略口径偏了」审计；不完整切片整笔拒绝入账、不推进水位。
- **乙锁定（冻结区）**：改口前必须先作废当日未完成草稿（`release_drafts`）与半截流水（冻结/拒绝行）并逐笔写「作废」审计，再写「改口审计」；成功行属已完结账本保留。不完整切片进待补齐冻结区，补齐（`/api/slices/{id}/supplement`）后同单放行才推进水位。
- **互斥账本**：每条流水带 `release_no` 单号、`caliber` 口径戳与 `policy_version`；同一放行单只能写同一口径，混写或请求显式口径与钉死策略不符一律 409 并记「策略口径偏了」；禁止无审计改口。
- **排队加锁**：改口侧与放行侧共用单机文件锁（`data/app.lock`，`flock` 排他），阻塞排队；后手检测到争用写「策略争用」审计，不静默通过。
- 历史库自动迁移补列，旧流水按甲口径回填 `RO-LEGACY-*` 单号。
